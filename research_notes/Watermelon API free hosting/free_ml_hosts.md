# Free or Effectively Free Hosting for the Watermelon AI Vision API (checked 2026-10-13)

## Can any provider host a Python FastAPI model continuously at no cost?

### Takeaway
Oracle Cloud Always Free is the only reviewed option that can plausibly run one small CPU inference VM continuously with no recurring compute charge, but “continuous” is not guaranteed because idle free VMs may be reclaimed and free capacity can be unavailable. Cloud Run and Modal are better-managed choices for low-volume usage that can remain within a monthly free allowance, but both scale to zero by default; Hugging Face Spaces is no longer actually free to create for FastAPI/Docker because a paid plan is now required.

### Cited Findings
- **Oracle Cloud Always Free VM:** Oracle says Always Free resources remain free for the life of the account in the tenancy’s home region. Its current main Always Free page describes up to two AMD micro VMs (1 GB each) and, for Always Free tenancies, a total of 2 Arm OCPUs and 12 GB RAM, plus 200 GB combined boot/block storage and 10 TB/month outbound transfer. It also says idle free VMs may be reclaimed after a seven-day window when 95th-percentile CPU, network, and (for A1) memory are all below 20%. — [Oracle Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)
- **Oracle account/capacity caveats:** Most users need a phone number and credit card to register; the card is not charged unless the account is upgraded. Free capacity is not reserved, and Oracle documents “out of host capacity” errors, advising users to try another availability domain or wait. — [Oracle Free Tier](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier.htm); [Oracle capacity troubleshooting](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/troubleshooting-out-of-host-capacity.htm)
- **Oracle documentation conflict:** Oracle’s main Always Free page currently states 1,500 OCPU-hours and 9,000 GB-hours/month (equivalent there to 2 OCPUs/12 GB for Always Free tenancy), while the separate current Arm Compute page states 3,000 OCPU-hours and 18,000 GB-hours/month. The Console limit for the actual tenancy should therefore be treated as authoritative before deployment. — [Oracle Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm); [Oracle Arm Compute](https://docs.oracle.com/en-us/iaas/Content/Compute/References/arm.htm)
- **Google Cloud Run:** Request-based Cloud Run includes 180,000 vCPU-seconds, 360,000 GiB-seconds, and 2 million requests per month, with the allowance aggregated by billing account and valued at `us-central1` tier-1 rates. Bangkok (`asia-southeast3`) is an available region. A Cloud Billing account is required even when only using Free Tier resources. — [Cloud Run pricing](https://cloud.google.com/run/pricing); [Google Cloud Free Program](https://docs.cloud.google.com/free/docs/free-cloud-features)
- **Cloud Run is not free always-on:** A no-traffic revision scales to zero by default. Keeping a minimum instance warm incurs billing; under request-based billing, idle minimum instances have discounted but nonzero CPU and memory prices. — [Cloud Run autoscaling](https://docs.cloud.google.com/run/docs/about-instance-autoscaling); [Cloud Run minimum instances](https://docs.cloud.google.com/run/docs/configuring/min-instances); [Cloud Run pricing](https://cloud.google.com/run/pricing)
- **Hugging Face Spaces:** CPU Basic is nominally $0/hour with 2 vCPU, 16 GB RAM, and 50 GB ephemeral disk, but Hugging Face now says creating a Gradio or Docker Space that runs on compute requires a paid plan. PRO costs $9/month and unlocks Gradio/Docker Spaces. Free CPU hardware sleeps after 48 hours of inactivity and cannot be configured never to sleep. — [Spaces overview](https://huggingface.co/docs/hub/spaces-overview); [HF pricing](https://huggingface.co/pricing); [Spaces hardware and sleep](https://huggingface.co/docs/hub/spaces-gpus)
- **Render:** A free public web service provides 0.1 CPU and 512 MB RAM, spins down after 15 minutes without inbound traffic, and usually takes about one minute to spin up. It receives 750 running-instance hours/month per workspace, but Render explicitly says free instances should not be used for production. — [Render compute plans](https://render.com/docs/compute-plans); [Render free services](https://render.com/docs/free)
- **Koyeb:** One free web service provides 0.1 vCPU, 512 MB RAM, and 2 GB SSD, is limited to Frankfurt or Washington, D.C., and must scale to zero after one hour idle. Koyeb describes it as a preview/hobby resource, not production. A credit card is required, with a temporary $29 pre-authorization hold documented. — [Koyeb instances](https://www.koyeb.com/docs/reference/instances); [Koyeb pricing FAQ](https://www.koyeb.com/docs/faqs/pricing)
- **Fly.io:** Fly no longer offers a durable free hosting allowance to new users. Its trial is only two VM-hours or seven days, whichever comes first; trial VMs auto-stop after five minutes, and all normal organizations require a card. — [Fly.io free trial](https://fly.io/docs/about/free-trial/); [Fly.io pricing](https://fly.io/docs/about/pricing/)
- **Railway:** Railway’s current Free plan is $0/month with $1/month of usage credit, capped at 1 vCPU, 0.5 GB RAM, 1 GB ephemeral disk, 0.5 GB volume storage, and a 4 GB image. The initial trial is a one-time $5 grant; Hobby is not free and costs at least $5/month. — [Railway plans](https://docs.railway.com/pricing/plans); [Railway pricing](https://railway.com/pricing)
- **Modal:** Modal’s Starter plan has no monthly platform fee and includes $30/month of compute plus 1 TiB/month outbound transfer; compute beyond the allowance is billed. Modal is serverless and its Web Functions can expose FastAPI/ASGI apps at persistent public URLs, but containers run only on demand rather than remaining continuously alive. — [Modal pricing](https://modal.com/pricing); [Modal Web Functions](https://modal.com/docs/guide/webhooks); [Modal endpoint URLs](https://modal.com/docs/guide/webhook-urls)

### Inferences
- For a literal **24/7 resident process at zero recurring compute cost**, Oracle A1 is the only credible candidate in this set, provided the account can obtain capacity and the workload is active enough not to meet Oracle’s idle-reclamation test. This is still best-effort infrastructure, not a free production SLA. — [Oracle Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)
- For **24/7 public URL availability rather than a continuously resident process**, Cloud Run or Modal can be effectively free at low traffic because the URL remains deployed while compute scales to zero; the trade-off is first-request latency and possible overage billing. — [Cloud Run autoscaling](https://docs.cloud.google.com/run/docs/about-instance-autoscaling); [Modal Web Functions](https://modal.com/docs/guide/webhooks)
- Hugging Face should now be described as **low-cost ($9/month minimum for a newly created FastAPI/Docker Space), not free**, even though CPU Basic has no additional hourly price. — [Spaces overview](https://huggingface.co/docs/hub/spaces-overview); [HF PRO](https://huggingface.co/pro)

### Gaps
- None of the reviewed free tiers provides a contractual production uptime SLA at no charge.
- Oracle’s official pages disagree on the current A1 hourly allowance; the tenancy Console must be checked before committing to an instance size.
- Modal’s public documentation reviewed here does not clearly state whether a payment card is required before using the recurring $30 Starter allowance.

## What sleeps or cold-starts, and how would that affect image diagnosis UX?

### Takeaway
Render has the most damaging documented free-tier UX (sleep after 15 minutes and roughly one-minute wake-up). Koyeb’s documented platform wake-up is 1–5 seconds after its one-hour idle period, while Cloud Run, Modal, and Hugging Face cold-start time depends heavily on container/dependency/model initialization. For diagnosis, the frontend must treat a cold start as a visible “starting analysis engine” state and should use job submission/polling rather than one fragile long HTTP request.

### Cited Findings
- **Render:** Free services sleep after 15 minutes of no HTTP/WebSocket traffic and take about one minute to wake. Local filesystem changes are lost at every redeploy, restart, or spin-down. — [Render free services](https://render.com/docs/free)
- **Koyeb:** The free instance must sleep after one idle hour and cannot disable or customize this. Koyeb says a deep-sleep VM typically wakes in 1–5 seconds, although application/model initialization can add time. — [Koyeb scale-to-zero](https://www.koyeb.com/docs/run-and-scale/scale-to-zero)
- **Hugging Face:** Free CPU Basic sleeps after 48 hours of inactivity, and visiting the Space restarts it. Docker Spaces explicitly support FastAPI and expose their configured port. — [Spaces hardware and sleep](https://huggingface.co/docs/hub/spaces-gpus); [Docker Spaces](https://huggingface.co/docs/hub/spaces-sdks-docker)
- **Cloud Run:** Zero is the default minimum instance count. Google notes that a request may wait for a new container to download/stream its image, run its entrypoint, load dependencies, and begin listening. Startup must complete within four minutes; request timeout includes startup time, and an HTTP request can be configured up to 60 minutes. Startup CPU boost can temporarily allocate extra CPU and is billable. — [Cloud Run autoscaling](https://docs.cloud.google.com/run/docs/about-instance-autoscaling); [Cloud Run development tips](https://docs.cloud.google.com/run/docs/tips/general); [Cloud Run container contract](https://docs.cloud.google.com/run/docs/container-contract); [Cloud Run limits](https://docs.cloud.google.com/run/quotas); [Cloud Run CPU boost](https://docs.cloud.google.com/run/docs/configuring/services/cpu)
- **Modal:** Web Functions cold-start on the first request and Modal says the boot can take a few seconds. Containers remain idle for 60 seconds by default before shutdown; configuring a longer warm window or minimum containers increases billed usage. Web requests have a 150-second timeout, and Modal documents an asynchronous submit-and-poll pattern for longer work. — [Modal Web Functions](https://modal.com/docs/guide/webhooks); [Modal cold starts](https://modal.com/docs/guide/cold-start); [Modal request timeouts](https://modal.com/docs/guide/webhook-timeouts)
- **Oracle VM:** A running VM does not scale to zero, but Always Free instances can be reclaimed as idle under Oracle’s utilization test; free users can also face capacity errors when creating/recreating an instance. — [Oracle Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm); [Oracle capacity troubleshooting](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/troubleshooting-out-of-host-capacity.htm)

### Inferences
- A realistic cold start for a vision service equals **platform boot + Python imports + model-weight loading**. Provider wake-up numbers alone are not the diagnosis delay; large PyTorch/TensorFlow dependencies and model initialization can dominate. Google and Modal both explicitly identify dependency/model initialization as cold-start work. — [Cloud Run development tips](https://docs.cloud.google.com/run/docs/tips/general); [Modal cold starts](https://modal.com/docs/guide/cold-start)
- For Watermelon AI, return `202 Accepted` with a scan/job ID quickly, then poll a status/result endpoint. The UI can say “กำลังเริ่มเครื่องวิเคราะห์” during cold start, distinguish timeout from diagnosis failure, and avoid retrying uploads blindly. Modal documents this exact job pattern, and it is portable to Cloud Run/Oracle. — [Modal request timeouts](https://modal.com/docs/guide/webhook-timeouts)
- Health-check pings used only to defeat free-tier sleep are not a reliable 24/7 strategy: they consume quotas, may violate the intended free-tier model, and do not eliminate restart/deployment events. The safer UX is explicit asynchronous work with retry/idempotency.

### Gaps
- Hugging Face does not publish a fixed CPU Space wake-up time; it varies with build/image/model initialization.
- Google does not promise a fixed Cloud Run cold-start duration; it publishes a four-minute startup deadline and optimization guidance instead.
- Koyeb’s 1–5 second number covers deep-sleep VM creation, not the complete import and model-load time of this project.

## Which option works for potentially large ML dependencies and model artifacts?

### Takeaway
Oracle A1 offers the most free persistent disk and RAM for a self-managed CPU model, while Modal is the strongest managed/serverless ML option for large artifacts. Hugging Face has generous ML-oriented resources but now costs at least the subscription fee. Cloud Run can handle substantial memory but free Artifact Registry storage is only 0.5 GiB; Render and Koyeb free instances are generally too small for a typical PyTorch/TensorFlow vision stack.

### Cited Findings
- **Oracle:** The main Always Free allowance provides 12 GB Arm RAM total and 200 GB combined boot/block storage in the home region, with up to 10 TB/month outbound data. — [Oracle Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)
- **Oracle architecture constraint:** The free high-memory A1 shape is Arm-based, and Oracle supplies Arm-compatible Oracle Linux/Ubuntu images. The AMD micro alternative has only 1 GB RAM and 1/8 OCPU per VM. — [Oracle Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)
- **Modal:** Starter includes $30/month compute; Modal Volumes are designed for ML weights, include up to 1 TiB free according to current pricing, and individual files can be up to 1 TiB. Modal recommends baking one model into an image or putting many/large models in a Volume. — [Modal pricing](https://modal.com/pricing); [Modal Volumes](https://modal.com/docs/guide/volumes)
- **Hugging Face:** CPU Basic supplies 2 vCPU, 16 GB RAM, and 50 GB ephemeral disk. Public Hub storage for free users is “best effort,” while the Space’s local disk is nonpersistent; model repositories can be mounted read-only into a Space. — [Spaces overview](https://huggingface.co/docs/hub/spaces-overview); [Spaces storage](https://huggingface.co/docs/hub/spaces-storage); [Hub storage limits](https://huggingface.co/docs/hub/storage-limits)
- **Cloud Run:** Services can allocate up to 32 GiB RAM and 8 vCPU, but those larger allocations are metered. Default memory is 512 MiB, startup must complete in four minutes, and HTTP/1 request bodies are capped at 32 MiB. Artifact Registry includes only 0.5 GiB-month free storage; colocating its repository with Cloud Run avoids cross-region transfer charges. — [Cloud Run limits](https://docs.cloud.google.com/run/quotas); [Cloud Run container contract](https://docs.cloud.google.com/run/docs/container-contract); [Artifact Registry pricing](https://cloud.google.com/artifact-registry/pricing)
- **Render:** The free runtime is 0.1 CPU/512 MB, free disk is ephemeral, persistent disks are unavailable on free web services, Hobby includes 500 build-pipeline minutes/month, and Hobby outbound transfer is 5 GB/month. — [Render compute plans](https://render.com/docs/compute-plans); [Render free services](https://render.com/docs/free); [Render build pipeline](https://render.com/docs/build-pipeline); [Render outbound bandwidth](https://render.com/docs/outbound-bandwidth)
- **Koyeb:** The free runtime is 0.1 vCPU/512 MB/2 GB SSD with no volume attachment. An uncompressed image may be smaller than 5 GB plus the instance’s local SSD (thus under 7 GB on the 2 GB free instance), and the documented included outbound allowance is 100 GB/month. — [Koyeb instances](https://www.koyeb.com/docs/reference/instances); [Koyeb storage constraints](https://www.koyeb.com/docs/reference/storage); [Koyeb pricing FAQ](https://www.koyeb.com/docs/faqs/pricing)
- **Railway:** Free is limited to 0.5 GB RAM, 1 GB ephemeral disk, 0.5 GB volume, and 4 GB image size, so the recurring $1 usage credit does not overcome the memory/artifact ceiling for most vision stacks. — [Railway plans](https://docs.railway.com/pricing/plans)

### Inferences
- Before choosing Oracle A1, build and test a `linux/arm64` image containing the project’s exact inference libraries and model. Arm compatibility—not raw RAM—is the main technical gate.
- For `legacy4`/`wide9`, a quantized ONNX model with `onnxruntime` is more likely to fit inexpensive CPU/serverless resources than a full training-oriented PyTorch image. The model should be loaded once per process/container, not per request.
- Render and Koyeb free tiers should be treated as API/proxy or health/demo hosts, not primary image inference hosts, unless measurement proves the complete resident set is safely below 512 MB and acceptable on 0.1 CPU. — [Render compute plans](https://render.com/docs/compute-plans); [Koyeb instances](https://www.koyeb.com/docs/reference/instances)
- For Cloud Run, place model weights inside the immutable image only if the image remains reasonably small; otherwise fetch/version them from object storage during deployment/startup and account for both storage cost and cold-start time. The 0.5 GiB Artifact Registry free allowance means a large image can create a small recurring charge even when runtime stays within the Cloud Run free tier. — [Artifact Registry pricing](https://cloud.google.com/artifact-registry/pricing); [Cloud Run development tips](https://docs.cloud.google.com/run/docs/tips/general)

### Gaps
- The project’s actual container image size, peak RSS during model load/inference, and measured CPU latency were not supplied; these must be measured for `legacy4` and `wide9` before a final provider decision.
- Cloud Run does not publish one simple maximum container-image size on the reviewed pages; practical deploy/startup performance should be tested with the real image.
- Provider build systems may change package/build timeout limits independently of runtime limits; prebuilding a multi-architecture Docker image in CI reduces this uncertainty.

## Is an “always-on and free forever” promise realistic, and what architecture split is safest for Watermelon AI?

### Takeaway
No hosted production API should be promised as both always-on and free forever. The safest Watermelon AI design is to keep the public web/API/data tier independent of vision compute, submit diagnosis as an idempotent job, run the default CPU model on a replaceable inference backend, and preserve a clear degraded path when that backend is waking or unavailable.

### Cited Findings
- Providers explicitly reserve behavior that conflicts with a hard always-on promise: Render can restart free services and says not to use them for production; Oracle may reclaim idle free VMs; Cloud Run scales to zero unless a billable minimum instance is configured; Hugging Face free CPU sleeps after 48 hours; Koyeb free sleeps after one hour; Fly’s “free” access is only a trial. — [Render free services](https://render.com/docs/free); [Oracle Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm); [Cloud Run autoscaling](https://docs.cloud.google.com/run/docs/about-instance-autoscaling); [Spaces hardware and sleep](https://huggingface.co/docs/hub/spaces-gpus); [Koyeb scale-to-zero](https://www.koyeb.com/docs/run-and-scale/scale-to-zero); [Fly.io free trial](https://fly.io/docs/about/free-trial/)
- Free offers can change materially: Hugging Face now requires a paid plan to create compute Spaces; Render reduced new Hobby bandwidth to 5 GB/month in April 2026; Koyeb discontinued its former $5.50 monthly credit; Fly replaced durable free allowances with a short trial. — [Spaces overview](https://huggingface.co/docs/hub/spaces-overview); [Render workspace plans](https://render.com/docs/new-workspace-plans); [Koyeb pricing FAQ](https://www.koyeb.com/docs/faqs/pricing); [Fly.io free trial](https://fly.io/docs/about/free-trial/)
- Cloud Run allows public unauthenticated access and supports a Bangkok region, while Modal exposes persistent public FastAPI/ASGI URLs and supports proxy-token protection when desired. — [Cloud Run configuration](https://docs.cloud.google.com/run/docs/configuring); [Cloud Run pricing/regions](https://cloud.google.com/run/pricing); [Modal endpoint URLs](https://modal.com/docs/guide/webhook-urls); [Modal proxy tokens](https://modal.com/docs/guide/webhook-proxy-auth)
- Render suspends services rather than charging when no payment method is present and bandwidth is exhausted; with a payment method it can bill overages. Koyeb requires a card and currently has no spending-limit feature. Google requires an active billing account and bills usage above free limits on a paid billing account. — [Render free services](https://render.com/docs/free); [Koyeb pricing FAQ](https://www.koyeb.com/docs/faqs/pricing); [Google Cloud Free Program](https://docs.cloud.google.com/free/docs/free-cloud-features)

### Inferences
- **Recommended production path:** use Cloud Run in Bangkok for the FastAPI vision service, request-based billing, `min-instances=0`, a strict `max-instances` cap, budget alerts, and a measured 1–2 GiB memory setting. This gives the best Thailand latency/operations balance and can be near-zero at low volume, but it must be presented as “free within quota,” not “free forever.” — [Cloud Run pricing](https://cloud.google.com/run/pricing); [Cloud Run configuration](https://docs.cloud.google.com/run/docs/configuring)
- **Recommended zero-cash prototype path:** test Oracle A1 first if an Arm64 build passes and capacity is available. Run the model and a small queue worker there, but keep deployment automation and backups ready so the service can move quickly if the VM is reclaimed. — [Oracle Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)
- **Recommended ML-native alternative:** Modal is attractive when traffic is sporadic or GPU experimentation may be needed. Its $30 recurring compute allowance, large free Volume allowance, public FastAPI support, and scale-to-zero model fit diagnosis jobs; keep a cost cap and accept cold starts. — [Modal pricing](https://modal.com/pricing); [Modal Volumes](https://modal.com/docs/guide/volumes); [Modal Web Functions](https://modal.com/docs/guide/webhooks)
- **Safest component split:** (1) static frontend/PWA stays on a static host; (2) authoritative Node API/data/storage remains independent; (3) the API accepts an image or signed object URL, creates an idempotent scan record, and dispatches to a separate vision service; (4) the client polls the authoritative API for `queued/running/succeeded/failed`; (5) images/results use durable object/database storage rather than inference-container disk; (6) provider-specific adapters select Cloud Run, Modal, or Oracle without changing the frontend API contract.
- The main diagnosis card should continue using the validated `legacy4` path. `wide9` and paid `claude` remain explicitly selected supplemental engines; infrastructure failover must not silently change engines or reuse `legacy4` accuracy claims for another engine.
- Do not “fail open” with a fabricated normal result. If inference is unavailable, preserve the upload/job state, report the outage plainly, allow retry, and keep the existing AI decision-support warning.
- A practical service target is **publicly reachable 24/7 with graceful cold starts and recovery**, not **a process guaranteed warm 24/7 at zero cost**. If instant first diagnosis is a product requirement, budget for one warm instance or a small paid VM.

### Gaps
- Final choice requires benchmarks from Thailand for: image upload time, cold start, model load, per-image inference, peak memory, and error/retry rate on each candidate.
- No provider reviewed here guarantees that current free allowances or prices will remain unchanged; pricing must be rechecked before launch and periodically afterward.
- The acceptable first-scan delay and monthly scan volume are not specified; those two product inputs determine whether scale-to-zero is acceptable and whether Cloud Run/Modal stays within free allowance.
